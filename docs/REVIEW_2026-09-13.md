## Findings

### 1. Full-constraint success is still not measured

[Ordinary evaluation](../src/robot_ai/evaluate/baseline.py) and both learned paths in
[evaluate/policy.py](../src/robot_ai/evaluate/policy.py) omit `hard_violation` when
calling `score_episode`. The scorer defaults it to all false. A report containing
`hard_violation: false` therefore does not demonstrate that limits were checked.
Only the first case's full trajectory is saved by each suite evaluation.

Repair the caller instrumentation, including joint-limit encounters at physics
resolution, and retain replayable per-case evidence or exact sufficient summaries.
Report which limits are modeled; do not invent thermal or structural measurements
for the rigid fixture. Renew selected/reference scores before promoting them.

PPO also checks hold error/speed only at control ticks, whereas evaluation checks
physics substeps. Its reward includes progress plus a flat failure penalty, unlike
the current EVALUATION formula. R2 repaired episode lifetime, but did not fully
close the reward/scorer contract. Resolve this before resuming PPO; it does not
explain the behavior-cloning result, which uses imitation loss.

### 2. The memoryless comparator is sensor-blind

[Runtime.act](../src/robot_ai/control/runtime.py) zeros the first 132 features:
the entire belief and decoded q/dq. [FeatureAdapter](../src/robot_ai/control/features.py)
provides no other sensor inputs. The comparator retains descriptor, goal, clock,
and previous command, but cannot respond to the robot's measured state.
[Training](../src/robot_ai/train/policy.py) uses the same masking.

Thus 63/64 versus 0/64 does not isolate recurrent-memory benefit. The guidance
itself introduced this defect by demanding the masking while also asking for a
competitive current-measurement baseline. Restore a separately trained feedforward
policy using current public values/masks/freshness/ages plus matched task/context,
with comparable capacity and training budget. Preserve the old result as a
sensor-removal ablation, not an adaptive-benefit claim. The adaptive policy still
uses one shared learned feeling.

### 3. The case-39 action-discontinuity diagnosis is contradicted by a matched query

The saved policy's largest adjacent command change occurs at ticks 22→23,
0.22→0.23 s. Its norm is **1.057406**. Earlier sign reversals already occur at
ticks 1→2 and later ticks, so this is not the first reversal.

Querying the actual training teacher on the policy's recorded physical states gives:

| Tick | Policy command | Teacher on that same state |
| --- | --- | --- |
| 22 | [0.01873, -0.50737] | [0.03238, -0.48967] |
| 23 | [-0.16414, 0.53411] | [-0.11914, 0.54460] |

The same-state teacher jump is **1.045306**, almost the policy jump. The old 0.169
teacher comparison used a different, teacher-driven trajectory at the same tick.
It did not identify an unnecessary neural discontinuity. These label queries do
not prove that a teacher-driven rollout is unstable, either.

Fresh packets do not resolve the question. At tick 23, true joint-2 velocity is
-2.583 rad/s while its causal packet estimate is +0.165 rad/s. This is compatible
with filtering during fast oscillation; it is not evidence of a timestamp bug or
accurate instantaneous feedback. Inspect how observer error, policy fitting error,
and feedback sensitivity interact from the onset of oscillation. A same-state
teacher query and a teacher-driven rollout answer different questions; retain both.

Case 39 misses the 0.030 m/s hold-speed limit at 0.2445 m/s despite only 3.333 mm
maximum hold error. Its 6,076.6 slew is an **integrated squared command derivative**,
not an instantaneous rate or measured structural load.

### 4. The action-delta experiment does not isolate the proposed cure

The three runs initialize selected update-15 weights, create fresh Adam state at
3e-4, and optimize teacher-forced sequences from the complete later data buffer.
Even weight zero raises action MSE from 0.001639 to 0.018664 after one update.
That shows a large continuation disturbance before attributing failure to the new
loss. The saved metric at each epoch is measured before that epoch's update.

Only pass 100 is evaluated on case 39 for each weight. Passes 25/50/75 exist but
have no corresponding selection in these reports. The final checkpoints all fail
and should not advance. This does not reject every saved candidate, all action-delta
objectives, or the controller architecture. Nor does fitting adjacent actions on a
teacher trajectory directly constrain the policy's closed-loop response elsewhere.
Any future continuation must first show that its zero-change/control condition is
understood; do not start another coefficient sweep from these conclusions.

### 5. Reference failures were incorrectly promoted to physical impossibility

The ordinary reference misses IDs 1, 30, and 53. The direct learned controller's
native report succeeds on IDs 1 and 30. Those reports still need the limit audit,
but they certainly do not support labeling the three cases physically infeasible.
SIMULATION already states the correct rule: reference failure does not prove
impossibility. Preserve all 64 cases and investigate the four packet failures.
Case 39 is a useful starting diagnostic, not the only legitimate target to repair.

### 6. Replay evidence and guidance have drifted

`test_clean_packet_features_replay_identically_through_runtime` constructs two
Runtime instances and feeds both identical packets. It never calls the real clone
collector. Clone artifacts save features/labels/case IDs, but not the original raw
packet sequences; the advertised collector-to-runtime replay is therefore not
established by that test. DAgger's immediate action recheck is also narrower than
independent reconstruction. Exercise the real collection path against a fresh runtime.

README pointed to R5b3, ROADMAP began at R5b1, and STATUS requested a decision after
R5b5 while retaining contradictory next steps. The roadmap had grown to 1,011 lines.
P6's “30 episodes” actually means 30 updates × 4 trajectories = 120 trajectories,
20,400 transitions. Historical R5b2/R5b3 also imposed a slew ceiling that R5b4 removed;
these are different acceptance rules and must not be presented as one unchanged gate.

The current Stage-A target returns explicitly to the user's ordering: declared
physical constraints, then >=61/64 development deadline/hold successes; report
smoothness and use it secondarily. The old 39.928 median-slew ceiling is not carried
into that target. This does not promote the 60/64 candidate or claim Stage B.

The planned single encoder-bias event needs a causal contract too: changing q1 can
also change its derived velocity channel. “Only channel 0 changes” is inappropriate
for that implementation. Verify direct and derived effects separately before P7.

## Direction

Make one authoritative packet-control evaluation and replay, diagnose the onset of
feedback oscillation, then make one evidence-supported correction. Establish a fair
current-packet comparator before claiming memory benefit. Keep independent packet
validation and a synchronized view of the current checkpoints in the deliverable.
Only then introduce one observable imperfection; coupled flex/base learning remains
downstream of validated reciprocal mechanics.

No architecture decision is required to perform these repairs. Discuss alternatives
with the user if the corrected evidence points to a change in supported sensors,
action interface, physical task, or learning architecture. A failed bounded run
should close an experiment with evidence, not generate another renamed schedule
or a blanket block on diagnostic and visualization work.

### The next diagnosis must be capable of changing a decision

C2's mixed-unit q/dq norm and teacher-path averages do not establish closed-loop
observer accuracy. Early trajectory divergence is real, but does not distinguish
estimation error, controller fitting and feedback sensitivity. C3b therefore asks
for per-joint errors, matched teacher queries, and (when needed) frozen teacher
loops using true versus decoded state. It limits the experiment to five named
cases and gives a next action for each outcome. A truth diagnostic is never a
deployable packet-control result.

Before that, C3a fixes a concrete visibility problem in
[packet_diagnostic.py](../src/robot_ai/visualize/packet_diagnostic.py): the cursor
uses `now/.01` for physics-rate arrays; the speed scale is the limit itself; and
q/actions use a zero lower bound. This can hide or misalign the very oscillation
being diagnosed. Measured packets and decoded dq are not plotted. A saved HTML
with these defects is not accepted synchronized diagnostic evidence.

Physical fixtures have a similar scope problem. The backlash check holds the
output fixed and compares terminal energy; it does not validate moving-output
gap crossing or trajectory convergence. The base ring-down test bounds energy by
its initial value, not by every preceding sample. Its terminal pose comparison
mixes metres and radians, so calling the whole tolerance “0.5 mm” is wrong.
The combined fixture's constant vertical preload subtraction does not establish
pose-dependent support equilibrium or reciprocal arm reactions. The next independent
physics package implements one real coupled pitch-base topology; more isolated
oscillator tests alone will not close P8.
